# 文件与媒体管理方案

本期目标是：**断网重启后仍能查看本地聊天记录、打开已完整缓存的附件。** 按当前消息结构实现，不做历史格式兼容。

## 1. 范围与分工

| 层                            | 本期职责                                                                                                                       |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `abd-im-sdk-core`             | 从本地消息解析资源和隐私限制；资源身份、共享任务与视频分片读取、取消、进度、完整性校验、缓存索引、容量设置、回收和账号生命周期 |
| `abd-im-sdk-js-wasm`          | 在现有 SDK 中导出类型、方法、事件及固定 I/O 桥接；使用同一个 `openIM.wasm`                                                     |
| Electron 主进程               | HTTP 到文件、执行 SDK 提供的 SQLite 语句、本地媒体协议、保存对话框和文件复制                                                   |
| React 界面                    | 调用 SDK，展示进度与错误，管理预览引用；消息和聊天记录中的媒体使用相同组件                                                     |
| React Native 桥接与移动客户端 | 后续接入同一原生 SDK；本期不修改桥接、播放器和移动页面                                                                         |
| 纯 Web                        | 保持远端预览和浏览器下载，不初始化桌面媒体存储                                                                                 |
| server / tools / 协议         | 无改动，沿用稳定对象地址和现有附件回收策略                                                                                     |

桌面调用链为：页面 → 现有 JS SDK → 同一个 Go WASM → preload / IPC → Electron I/O。不新增 Electron 专用 WASM、第二个 SDK 会话或原生 Go 进程。移动端使用相同的 Go 核心和原生 I/O，不复制桌面业务逻辑。

## 2. 本期功能边界

基本行为包括：下载共用任务、取消删除未完成文件、关闭文件并校验后发布完成、本地优先读取、按账号隔离、容量回收、清缓存保护用户另存文件。

本期交付基础离线使用，不包含全局下载中心、按会话自动下载配置或下载记录管理。视频播放和完整缓存复用同一个分片索引与请求，已读取的分片持久保存，后台只补齐缺失分片。下载任务不提供暂停操作，也不恢复跨重启的活动任务；重启后下一次播放或下载会复用已有分片。

平台桥接只执行 SDK 所需的固定 I/O，不建立插件或存储 Provider 框架。

## 3. 使用行为

- **图片**：显示消息时只下载、缓存缩略图；点击预览后再下载、缓存原图。预览先显示缩略图，原图下载完成后替换。两份缓存分别登记，共用容量限制和清理逻辑。
- **文件**：点击后完整下载到内部缓存，再使用现有 Markdown、文本、图片或 PDF 预览。预览保留现有大小限制；其他格式可以另存为。
- **视频**：点击播放获得 SDK 媒体地址，播放器始终通过这个地址读取。完整文件或已有分片优先本地读取，缺失分片按需以 HTTP Range 下载并保存；拖动播放优先于后台补齐。播放与后台缓存共用分片和进行中的请求，不重复下载正文。关闭预览后后台缓存继续，取消只停止后台补齐；已校验的分片保留。全部分片齐全后生成完整文件，可离线播放与另存为。
- **另存为**：打开系统保存对话框，将完整缓存复制到用户选定的位置；不用网络重新下载。副本由用户管理，不登记另一套下载历史。
- **失败或取消**：不登记不完整文件为完成；删除未校验的临时数据，用户可以重新发起。视频已校验分片保留并可复用；离线缺失分片返回错误，不伪装成完整文件。
- **聊天记录媒体页**：图片、视频、文件复用消息组件及同一个 SDK 缓存。
- **存储设置**：展示当前账号的缓存占用，设置容量上限，手动清理缓存。正在使用的文件保留；用户另存的副本和消息记录不删除。

SDK 登录先初始化本地消息数据库，再在后台连接服务器。离线使用依赖曾经成功使用过的本地账号及数据；首次登录、发送消息、获取未缓存附件仍需联网。

## 4. 资源和状态

界面只提交以下消息定位，不能提交下载 URL、路径或可修改的隐私标记：

```ts
interface MediaMessageRef {
  conversationID: string;
  clientMsgID: string;
  variant: "source" | "snapshot" | "big" | "video";
}
```

SDK 从当前账号的消息数据库读取消息，只接收成功状态的消息。`attachedInfoElem.isPrivateChat` 内容不能进入持久缓存或导出接口。

```text
resourceKey = SHA-256(accountID + "\0" + kind + "\0" + UUID + "\0" + variant)
```

文件使用 `fileElem.uuid`，原图使用对应 Picture UUID，视频使用 `videoUUID` 或 `snapshotUUID`。图片缩略图使用原图 UUID 和 `snapshot` 变体作为身份，SDK 从原图稳定地址派生固定的 `?height=640&type=image&width=640` 请求，复用后端已有的缩略图生成与缓存。不依赖消息里的缩略图 UUID、大小或 URL，也不上传另一份图片。

原始附件缺少 UUID、有效大小或稳定 `/object/...` 地址直接报错。派生缩略图下载前的大小为 `-1`，完成后登记实际大小。发送中的 Blob 预览沿用现有流程，发送成功后通过本地消息接入缓存。

任务状态为 `idle / queued / downloading / completed / failed / cancelled`。活动任务只保存在 SDK 内存。完整文件是否可读取取决于完整索引和文件实际大小、修改时间；视频分片按各自的长度、修改时间和对象版本验证；状态和算法只在 Go 核心实现。

## 5. 存储与下载

### 5.1 完整文件

```text
<media-root>/<account-hash>/
  index.sqlite
  objects/<resource-key>
  pending/<resource-key>
  pending/<resource-key>-<part-offset>
  parts/<resource-key>/<part-offset>
```

原生端位于 SDK 数据目录的 `media` 下；桌面位于应用 `userData/OpenIMData/media` 下。消息数据库继续使用现有原生 SQLite / WASM IndexedDB 路径。

媒体索引的表结构、建表、增删查改 SQL 和记录解析由 `abd-im-sdk-core` 统一维护，原生与 WASM 共用同一份实现。`media_resources` 保存资源、完整文件元数据，或视频分片列表、各分片文件元数据及强 ETag；`media_settings` 保存当前账号的容量设置。

SQLite 使用 WAL 写入日志模式。原生端复用现有 SQLite 驱动；桌面 `node:sqlite` 只打开索引文件并执行 SDK 提供的 SQL、返回查询结果，不定义媒体表或决定记录的保存与删除。SDK 只创建当前表结构，不建设旧版本迁移层。

下载流程：

1. SDK 查消息、检查限制、计算资源键。已有有效完整缓存则直接返回。
2. 同一资源共用任务，通过两路后台并发队列发送完整 GET；另一路保留给视频播放读取。
3. 平台仅请求当前 API 来源的稳定对象地址，桌面固定使用 Node `fetch`，原生端使用 Go HTTP；跟随受限次数的 HTTP(S) 跳转，将正文直接写入 `pending`。签名 URL 不持久化，也不作为资源身份。
4. 平台限制接收字节数，返回 HTTP 状态、实际长度、Content-Length、MIME 和关闭结果。
5. SDK 要求 HTTP 200，原始附件实际长度与消息声明相符；派生缩略图限制接收量不超过缓存上限，登记实际长度。存在的 Content-Length 必须与实际长度相符；然后移入 `objects`、写入索引并发布完成。
6. 失败、取消或退出时清理未完成数据。启动时清空 `pending`，不恢复任务。

普通附件正文不经过 WASM 或 IPC 整体复制。稳定地址当前返回 MinIO 签名 GET，服务端和 tools 无需修改。图片和普通文件继续使用完整 GET；视频使用下面的共享分片路径。

### 5.2 视频共享分片

- 固定 1 MiB 分片，末片按消息声明的总长度截断。SDK 为每个资源、每个偏移维护唯一进行中的请求；播放、拖动与后台补齐共用它。后台最多占两路，保留一路供播放器按需读取，避免下载队列阻塞播放。
- 先读取首片建立对象版本。每次远端请求必须返回 206、准确的 Content-Range、总长度及实际分片长度；首片必须提供强 ETag，后续发送同一 ETag 的 If-Match，并校验返回 ETag。稳定对象地址跳转到签名地址时保留 Range 与 If-Match。
- 不增加能力探测、Last-Modified 兜底或完整 GET 回退。412 或版本不符使当前读取失效并删除该版本分片，避免混合对象。普通网络错误保留此前已验证的分片。
- 正文由平台写入分片临时文件，SDK 校验后才发布到 `parts` 并更新索引。播放器收到读取许可后由平台直接读取分片；正文不经过 WASM/IPC。
- 所有分片齐全才合并并原子发布完整文件，完成索引。分片副本在最后一个读取引用关闭后删除，避免正在输出的响应失去文件；启动时清理完整资源遗留的分片副本。已打开的播放地址继续有效，后续读取改用完整文件。重启只恢复已保存分片，不恢复后台任务。

## 6. 本地读取与回收

SDK `openMedia` 对普通附件验证完整文件，对视频允许创建按需读取引用；`closeMedia` 释放引用。Electron 返回随机能力 URL：

```text
abd-media://cache/<file-reference>
```

主进程只读取引用对应的文件或 SDK 许可的分片，支持 GET、HEAD 和单段 Range。视频响应通过流逐片读取，Range 请求不等待整段或整个视频下载。原生 I/O 使用相同的 SDK 分片读取回调，通过账号会话内的本地 HTTP 地址提供给播放器。关闭引用、退出或切换账号后引用失效；不接受页面传入任意磁盘路径。协议限制响应类型并设置 CSP 与 `nosniff`，主动内容使用现有安全预览。

默认缓存上限为 2 GiB，完整文件和视频已保存分片共同计入占用，配置按账号持久化。SDK 按最后访问时间删除最久未使用的缓存，为新文件腾出空间；跳过正在使用的文件。单个文件超过上限时提示错误，用户可调整上限。空间不足、删除失败和网络错误返回实际错误，不自动切换下载实现。

正常 SDK 退出会取消任务、等待未完成文件清理、关闭索引。Electron 退出或渲染进程退出时也终止宿主 I/O 并清理临时目录，已完成的缓存保留。

## 7. 接口

现有 JS SDK 新增：

- `getMedia(ref)`：资源快照。
- `cacheMedia(ref)`：完整缓存，与已有任务合并。
- `cancelMedia(key)`：普通附件取消并清理临时数据；视频停止后台补齐，进行中的共享分片可以继续供播放器读取。
- `openMedia(ref)` / `closeMedia(fileRef)`：读取引用；视频支持缺失分片按需加载。
- `getMediaCacheUsage()`：占用和设置。
- `setMediaCacheSettings({ maxBytes })`：保存容量设置并回收。
- `clearMediaCache()`：清理未使用的内部缓存，返回实际剩余占用。
- `OnMediaChanged`：进度与状态事件。

原生端通过 `open_im_sdk` 的对应回调接口导出。React Native 只需在自己的项目中封装这些接口。桌面的 `window.electronAPI.media.save(fileRef, name)` 负责系统保存对话框和复制；固定的 `media.storage` 桥接服务于 Go SDK。

## 8. 构建与验收

本次修改涉及 `abd-im-sdk-core`、`abd-im-sdk-js-wasm`、`abd-im-web`。开发依赖指向相邻的本地 JS SDK，确保接口、类型和 WASM 同步；发布时需一并发布匹配的 SDK 包与应用。

重新构建现有 WASM：

```sh
# abd-im-sdk-core
GOOS=js GOARCH=wasm go build -trimpath -ldflags '-s -w' -o ../abd-im-sdk-js-wasm/assets/openIM.wasm ./wasm/cmd
# abd-im-sdk-js-wasm
pnpm build
# abd-im-web
pnpm build
```

验收重点：

- 联网缓存 → 退出 Electron → 停止附件服务器 → 重启 → 本地消息和完整附件仍可读。
- 普通附件的并发访问只有一次正文请求；视频播放与后台下载中每个分片只请求一次，拖动只请求缺失分片；不同账号互相隔离。
- 只显示图片气泡时不请求原图；点击预览才下载原图。缩略图与原图缓存后均可离线读取。
- 取消、长度不符和 404 不登记完成，未完成文件被清理。
- 阅后即焚消息被 SDK 拒绝缓存；读取引用释放后不能继续访问。
- 视频 Range 返回正确字节，首片和末片校验覆盖 206、Content-Range、ETag/If-Match、412 与截断响应；重启后复用分片、完整缓存离线播放；正在使用的文件不被清理，另存副本不被清理。
- 原生 Go 测试和真实 Electron + WASM 集成测试覆盖这些核心行为，纯 Web 回归现有附件预览。
- Windows/macOS 的系统保存对话框、文件权限和实际视频播放仍需在对应平台验证；当前 Linux 环境不能代替这两项平台验收。
