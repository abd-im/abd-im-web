# ABD-IM 我的 Agent 原型规格

状态：当前原型规范

本文件定义 ABD-IM Web 中面向普通用户的 Agent 调用入口、消息建议和连接设置。跨 Web、Server、Protocol、CLI 与 SDK 的完整边界见 [ABD-IM Agent API：权衡方案](../agent-api-plan.md)。

## 1. 产品目标

首期验证五个通用任务：

1. 用户通过固定的“我的 Agent”入口调用自己连接的外部 Agent。
2. 用户可以像使用 DeepSeek、豆包或 GPT 一样提出日常问题、作业和难题，并连续追问。
3. Agent 可以接收现有附件，读取聊天、查找联系人并执行已有 IM 动作。
4. 用户可在普通聊天中生成可编辑草稿，或为指定会话开启 AI 接管。
5. Agent 结果可以直接分享给真实联系人或群聊，不生成公开链接。

通用问答是基础价值，IM 上下文和动作是差异化价值。工作、生活、学习和兴趣场景使用同一套入口；产品不建立工作或生活专用对象。

## 2. 产品边界

| Web 提供                   | Web 不提供                         |
| -------------------------- | ---------------------------------- |
| 一个稳定的“我的 Agent”入口 | 多个 Agent 头像或 Agent 市场       |
| Agent 会话、历史和附件     | Agent 自身的记忆、计划或定时任务   |
| Provider 与 Connector 状态 | 模型内部 thread、prompt 或长期状态 |
| 输入框魔杖与草稿回填       | `@Agent` 私密群消息协议            |
| 现有 IM tools 的动作状态   | 投票、回应、消息置顶或群话题       |
| 联系人和群聊选择分享       | 公开任务链接                       |

Codex、Hermes Agent 和 OpenClaw 是可替换 Provider，不是多个社交联系人。首期前台只有一个“我的 Agent”身份，通讯录只显示真实联系人。

## 3. Agent 会话

### 信息结构

- 左栏：消息、通讯录、我的 Agent 和设置。
- 中栏：我的 Agent 状态、新对话、搜索和最近 Agent 会话。
- 主区：当前 Agent 会话和运行状态。
- 底部：文字、现有附件、响应方式和发送。

### 行为

1. “新对话”创建空白 Agent 会话并聚焦输入框。
2. Agent 名称保持“我的 Agent”，状态显示当前 Provider，例如“Codex · 已连接”。
3. Provider 可以在设置中切换，不增加新的 Agent 联系人。
4. Agent tool call 用紧凑状态表示，例如“读取 3 个会话”“创建周末碰面群”。
5. 对话可以分享给真实联系人或群聊，不复制链接。
6. Web 不显示“已了解 N 项”、记忆列表、已安排任务或项目分组。

### 附件

- 支持浏览器上传文件和图片。
- 支持拖放附件。
- 不提供本地工作目录或文件夹入口。
- 附件由 Connector 以引用交给 Provider；Web 不声称由 ABD-IM 生成文件。

## 4. 普通消息中的 Agent

- 输入框左下角魔杖调用“我的 Agent”。
- 点击魔杖主体直接生成建议；旁边的下箭头才展开一行本次指令，生成后自动清空。
- Agent 按需读取当前会话，结果直接填入草稿。
- 用户可以编辑草稿，再通过原生消息发送流程发送。
- 建议魔杖固定在输入框左下角，AI 接管固定在会话右上角；开启其中一个不会隐藏另一个。
- AI 接管使用分体按钮：主体直接启用或暂停，旁边的下箭头设置可选的一句话接管指令。
- 接管指令按当前会话保留，建议指令只作用于本次 run；两者都不是 Agent 长期记忆。
- 群聊也使用本机魔杖，不把 User-bound Companion 伪装成群成员。
- 群聊复用既有入站消息和发送能力提供接管，但不展示 `@Codex` 临时调用或仅本人可见群消息。
- 消息操作只展示现有客户端与 Agent tools 已支持的能力。

## 5. 设置

设置使用桌面双栏布局，移动端转换为顶部横向分类导航。

| 分类       | 配置内容                                               |
| ---------- | ------------------------------------------------------ |
| 常规       | 语言、发送按键和空白会话建议                           |
| Agent 连接 | Provider、Connector 状态、重新连接和 Provider 设置入口 |
| 消息协助   | 总开关、IM tools 总开关、草稿行为和会话 AI 接管状态    |
| 通知       | run 完成、需要补充输入和建议就绪提醒                   |
| 数据       | Agent 会话、附件引用、调用记录导出和清空历史           |

设置不提供 ABD-IM memory、schedule、planner、自定义人格或逐条记忆管理。Provider 支持这些能力时，只提供“打开 Agent 设置”的外部入口。

## 6. 演示数据

Agent 会话包含：

- 解释一道物理题：分析用户上传的题图，给出受力关系并支持继续追问。
- 回答日常问题：解释为什么会有极光，不调用 IM tool。
- 安排周末碰面：读取两个私聊、创建群聊并发送两个时间方案。

普通 IM 包含“周末碰面”、苏望舒和“城市漫步群”，避免把产品默认呈现为办公工具。

## 7. 原型验收

原型路径：[index.html](index.html)

- 只显示一个“我的 Agent”，Provider 仅作为连接状态出现。
- 通讯录和分享选择器只显示真实联系人。
- 没有已安排任务、项目分组、平台记忆或持续学习设置。
- 首屏先显示通用问答和题目讲解，同时保留社交协调与 IM 操作演示。
- 输入框魔杖可一键生成草稿，也可从下箭头附加本次指令；用户发送前可以编辑。
- 所有消息会话都固定显示左下角建议魔杖和右上角“AI 接管”，开启接管时魔杖仍然存在。
- “AI 接管”可一键启停，也可从下箭头附加会话指令。
- 不输入任何指令时，接管和建议都能直接执行。
- 群聊不出现 `@Codex` 私密调用或仅本人可见消息。
- 设置可以切换 Provider、重新连接 Connector、开关 Agent 调用与 IM tools。
- 不出现投票、回应、消息置顶、话题、编辑和转发等首期不可用 Agent 能力。
- 分享通过联系人或群聊选择完成，不复制链接。
- 桌面和移动视口无文字遮挡、横向溢出或脚本错误。
